httk.workflow.postprocessing¶

Run one provider-owned postprocess script against one collected job.

Fields: a manifest script name, workspace/job identifiers, an output directory, the process return code, and captured stdout/stderr.

Postprocess output never lands in the job payload: it is written under a workspace-level postprocess/ tree, so a finished job may be sealed immediately and still be postprocessed later without disturbing the bytes the seal covers. The output root is <workspace.root>/postprocess/ by default, the workspace setting postprocess.directory when set (an absolute path outside the workspace), or a per-invocation override (a relative path resolves against the current directory; it must also land outside the workspace); the per-job directory below it mirrors payload placement as <root>/<placement>/<job_key>/<script name>/.

The script runs with its cwd set to that per-job output directory and receives HTTK_WORKFLOW_WORKSPACE_DIR and HTTK_WORKFLOW_JOB_DIR for the workspace and the immutable payload (read-only from the script’s perspective), HTTK_WORKFLOW_POSTPROCESS_DIR for the output directory, and HTTK_WORKFLOW_WORKDIR / HTTK_WORKFLOW_DATA_DIR for the collected job’s result directories when those exist. Those are the only variables exported from the reserved HTTK_WORKFLOW_ namespace; all others in it are removed before launch. Scripts resolve only from the registered provider or an explicit package directory; job payloads and pinned workflow trees are never trusted as script sources.

Every completed run (any exit status) leaves a receipt <output_dir>/.httk-postprocess.json naming the script, the workflow, the job, the run times, the exit status, and the script’s declared outputs patterns as they were at run time. A stale receipt is removed before launch, so a timeout or launch failure leaves none. collect_postprocess() reads the receipts (it needs no provider) and describes each job’s declared output files as file records; it collects only from the workspace’s own postprocess/ tree, never from a postprocess.directory elsewhere or a per-invocation override. The output directory is reused between runs, so a glob pattern also matches stale files an earlier run left that a later run did not rewrite.

httk.workflow.postprocessing.postprocess_root(workspace, override=None)[source]¶

Resolve the output root all this workspace’s postprocess output lands in.

Precedence is the per-invocation override, then the postprocess.directory application setting, then <workspace.root>/postprocess. The setting must be an absolute path outside the workspace; a relative override resolves against the current directory and must also land outside the workspace.

Parameters:

  • workspace (httk.workflow.workspace.Workspace) – The workspace whose postprocess output root to resolve.

  • override (str | None) – A per-invocation output root that wins over the setting.

Returns:

The resolved absolute output root.

Raises:

ValueError – If the root is inside the workspace (other than the default), or the setting is relative.

Return type:

pathlib.Path

httk.workflow.postprocessing.collect_postprocess(workspace, script, *, states=('succeeded',), placement=None, jobs=None, on_skipped=None, steps=None, force=False)[source]¶

Describe the declared output files of script’s last run on each selected job.

Jobs are selected exactly as job_records() selects them. Each job’s receipt decides what is collected: no receipt, a failed run, a script declaring no outputs, or nothing matching skip the job; an unusable receipt, a missing literal (required) output, or a receipt rewritten while the files were hashed make it an error. Files reached through a symlink, or with a dot-prefixed component (the receipt itself among them), are never collected. File URLs have the form data/<workspace name>/<workspace-relative path> like job files; nothing is read from the provider and nothing is created.

Parameters:

  • workspace (httk.workflow.workspace.Workspace) – Read jobs and their postprocess output from this workspace.

  • script (str) – Name the postprocess script whose output to collect.

  • states (collections.abc.Iterable[str]) – Select the stopped states to report.

  • placement (str | pathlib.PurePosixPath | None) – Restrict results to this placement and its descendants.

  • jobs (collections.abc.Iterable[str] | None) – Collect only these jobs and their descendants.

  • on_skipped (collections.abc.Callable[[str], None] | None) – Receive the job key of every selected job dropped for an unreadable job.json, forwarded to job_records.

  • steps (collections.abc.Iterable[str] | None) – Collect only the jobs at one of these steps, as job_records selects them.

  • force (bool) – Collect unlocked jobs (debug mode) too; without it each is an error.

Returns:

A lazy iterator with one item per selected readable job.

Raises:

ValueError – If script is not a single path component, or the postprocess root is not inside the workspace (a postprocess.directory setting elsewhere).

Return type:

collections.abc.Iterator[CollectedPostprocess]
